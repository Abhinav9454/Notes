Unit 1: JS Engine & Memory

1. JavaScript Engine Architecture, V8 & Execution Context

Runtime & Memory Heap
⚡ The Heart of Modern Web Programming: JavaScript is a single-threaded, non-blocking, asynchronous, concurrent programming language featuring a Call Stack, an Event Loop, and a dynamic Memory Heap.

1. The V8 Engine Internal Pipeline

Google's V8 (used in Chrome and Node.js) does not interpret JavaScript line-by-line; it uses Just-In-Time (JIT) compilation:

  1. Parser: Reads JavaScript source code string and constructs an Abstract Syntax Tree (AST).
  2. Ignition (Bytecode Interpreter): Fast interpreter that compiles AST into compact bytecode and executes immediately.
  3. TurboFan (Optimizing Compiler): Monitors hot functions running repeatedly (Type Feedback) and recompiles them into hyper-optimized machine CPU opcodes. If types mutate (polymorphism), it deoptimizes back to bytecode.

2. Execution Context & The Two-Phase Lifecycle

Whenever JavaScript code executes, it runs inside an Execution Context containing: Variable Environment, Lexical Environment, and the this binding.

Execution PhaseEngine OperationsEffect on Variables & Functions
Phase 1: Memory Creation Phase
(Hoisting)		 Scans code for declarations. Allocates memory addresses in the Call Stack / Heap before executing a single line of code. • Function declarations are fully loaded into memory.
• var initialized to undefined.
• let and const allocated in uninitialized state (Temporal Dead Zone / TDZ).
Phase 2: Execution Phase Executes code line by line, evaluating expressions, assigning runtime values, and invoking functions. Variables receive their assigned values; functions execute and push new stack frames onto Call Stack.

🎯 Top Frontend Interview Questions

Q: What is the Temporal Dead Zone (TDZ) and why does let/const throw a ReferenceError while var returns undefined?

Answer: Both var and let/const are hoisted by the JavaScript engine during Phase 1 (Creation Phase).
However, var is initialized with undefined at the start of its scope. Accessing it before declaration yields undefined.
let and const are placed in the Temporal Dead Zone (TDZ) — the temporal region between entering the scope and reaching the line where the variable is explicitly declared. Accessing a variable in the TDZ throws an immediate ReferenceError: Cannot access 'x' before initialization. TDZ prevents silent bugs and enforces clean coding hygiene.

2. Primitives vs. Reference Types & Memory Allocation

Stack vs Heap

JavaScript has 7 primitive types and 1 reference type (Object). Understanding how they are allocated in physical memory is critical to avoiding mutation side-effects.

Memory CategoryData TypesPhysical Storage LocationCopying Mechanism
Primitive Types string, number, boolean, undefined, null, symbol, bigint Call Stack: Fixed-size memory cell directly inside the stack frame. Copied by Value: Creating a copy duplicates the raw value independently.
Reference Types Object, Array, Function, Date, Map, Set Memory Heap: Dynamic, unstructured memory pool. The Call Stack only holds a 64-bit pointer reference address! Copied by Reference: Creating a copy copies only the pointer address, pointing to the exact same heap object!

1. Shallow Copy vs. Deep Copy in Production

clone.js
const user = {
  name: 'Alex',
  skills: ['JavaScript', 'SQL'],
  address: { city: 'San Francisco' }
};

// 1. Shallow Copy (Spread Operator): Clones top-level only!
const shallowCopy = { ...user };
shallowCopy.name = 'Jordan';             // Safe: Does not mutate original user
shallowCopy.skills.push('React');        // BUG! Mutates user.skills in both objects!

// 2. Modern Native Deep Copy (ES2022 structuredClone):
const deepCopy = structuredClone(user);
deepCopy.skills.push('Node.js');         // Safe: user.skills remains untouched!

🎯 Top Frontend Interview Questions

Q: Why is JSON.parse(JSON.stringify(obj)) an anti-pattern for deep cloning objects?

Answer: While JSON.parse(JSON.stringify(obj)) is frequently used for quick deep cloning, it has catastrophic edge cases:
1. Drops Functions: Any object methods or functions are silently deleted.
2. Destroys Special Objects: Date objects are converted to plain strings; RegExp objects become empty objects; Map and Set lose all keys.
3. Circular References: Throws TypeError: Converting circular structure to JSON.
4. Converts undefined and NaN: undefined is stripped; NaN and Infinity turn into null.
Modern Solution: Always use native structuredClone(obj) or Lodash cloneDeep().

🎯 Top Frontend Interview Questions

Q: Does const prevent mutation of object properties or array elements?

Answer: NO. const creates an immutable binding (variable pointer), NOT an immutable value.
When declaring const user = { name: 'Alex' };, the variable user cannot be reassigned to point to another memory address (user = {} throws a TypeError).
However, the underlying object in the heap can be freely mutated: user.name = 'Jordan'; works without error.
To make an object's properties truly immutable, you must use Object.freeze(user);.

4. Operators, Implicit Coercion & Truthy/Falsy Truth Tables

Coercion & Equality

JavaScript is dynamically and weakly typed. Operators frequently trigger implicit type conversions (coercion) according to the ECMAScript Abstract Operations specification.

1. Strict Equality (===) vs. Loose Equality (==)

=== compares both value AND data type without coercion. == attempts implicit type conversion first before comparing:

equality.js
// Loose Equality Traps:
console.log(0 == false);        // true (false coerced to 0)
console.log("" == 0);           // true ("" coerced to 0)
console.log(null == undefined); // true (ECMAScript special rule)
console.log([] == false);       // true ([] coerced to "" then to 0)
console.log([] == ![]);         // true (![] is false -> [] == false -> 0 == 0)

// Strict Equality (Safe & Predictable):
console.log(0 === false);        // false
console.log("" === 0);           // false
console.log(null === undefined); // false

const userSettings = { animationSpeed: 0, theme: "" };

const themeGood = userSettings.theme ?? "dark";       // "" (Preserved correctly!)

🎯 Top Frontend Interview Questions

Q: Explain why 1 + "2" returns "12" while "5" - 2 returns 3.

Answer:
• The + operator serves a dual purpose in JavaScript: numeric addition AND string concatenation. According to the ECMAScript spec, if either operand is a string, the + operator coerces the other operand to a string and performs string concatenation: 1 + "2" → "1" + "2" → "12".
• The - operator has NO string operation defined. It only performs numeric subtraction. Therefore, the engine coerces the string "5" to the number 5 via ToNumber(): 5 - 2 → 3.

const fruits = ['Apple', 'Banana', 'Cherry'];
fruits.customProperty = 'Trap!';

🎯 Top Frontend Interview Questions

Q: Why should you avoid using for...in to iterate over arrays?

Answer: for...in was designed specifically for inspecting object keys, NOT array items:
1. Iterates Prototype Properties: If any third-party library or script added methods to Array.prototype, for...in will iterate over those method names as well!
2. Keys are Strings: The indices are returned as strings ("0", "1"), breaking numeric math (e.g. index + 1 → "01").
3. No Guarantee of Order: Modern engines do not strictly guarantee chronological index ordering for for...in.
Best Practice: Use for...of or standard for (let i = 0; i < arr.length; i++) for arrays.

Function Types & Execution

2. Rest Parameters vs. Spread Operator

functions.js
// Rest Parameters (...args): Gathers remaining arguments into a true Array
function calculateTotal(taxRate, ...prices) {
  const subtotal = prices.reduce((acc, curr) => acc + curr, 0);

🎯 Top Frontend Interview Questions

Q: What are the 4 fundamental differences between Arrow Functions and Regular Functions?

Answer:
1. No this binding: Arrow functions do not define their own this; they retain the this of the enclosing lexical context.
2. No arguments object: Arrow functions do not possess the legacy arguments array-like object (use rest parameters ...args instead).
3. Cannot be used as Constructors: Arrow functions lack a [[Construct]] internal method and have no prototype property; calling new ArrowFn() throws a TypeError.
4. No duplicate named parameters: Arrow functions disallow duplicate parameter names even in non-strict mode.

7. Scope Chain & Lexical Closures

Closures & Data Privacy

A Closure is the combination of a function bundled together with references to its surrounding lexical environment, allowing an inner function to access an outer function's scope even after the outer function has returned and exited the Call Stack.

1. Data Encapsulation using Closures

counter-closure.js
function createSecureAccount(initialBalance) {
  let balance = initialBalance; // Private state! Completely inaccessible from outside.

  return {
    deposit(amount) {
      if (amount <= 0) throw new Error("Invalid deposit amount.");
      balance += amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createSecureAccount(1000);
account.deposit(500); // 1500
console.log(account.balance); // undefined (Private state is protected!)

2. The Classic for-loop setTimeout Closure Puzzle

loop-closure.js
// THE BUG with var (Function scoped):
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 100);
}
// Outputs: 3, 3, 3 (Shared single variable i in memory!)

// THE FIX with let (Block scoped):
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 100);
}
// Outputs: 0, 1, 2 (Engine creates a new lexical scope binding for each iteration!)

🎯 Top Frontend Interview Questions

Q: How do closures cause Memory Leaks in Single-Page Applications (SPAs) and how do you prevent them?

Answer: Closures keep references to variables in their parent scope alive in the heap for as long as the inner function is reachable.
Common Memory Leak Scenario: Attaching an event listener (e.g. window.addEventListener('resize', () => { /* references heavy DOM node */ })) creates a closure holding onto that DOM node. If the page component unmounts but the window event listener is never removed via removeEventListener, the garbage collector cannot reclaim the component, causing a detached DOM tree memory leak!
Prevention: Always clean up subscriptions, event listeners, and timers (clearInterval) when components unmount.

8. The "this" Keyword & Dynamic Binding Rules

this Binding & Call/Apply/Bind

In JavaScript, the this keyword is NOT static; its value is dynamically determined by how and where a function is called (the call-site), with the sole exception of arrow functions.

1. The 4 Deterministic Rules of "this" Binding

Binding RuleInvocation PatternWhat 'this' Evaluates To
1. Default Binding Standalone function call: foo() window (browser) or global (Node). In strict mode ('use strict'), it is safely undefined!
2. Implicit Binding Method invocation: user.getProfile() The object immediately preceding the dot (user).
3. Explicit Binding fn.call(obj), fn.apply(obj), fn.bind(obj) Explicitly forces this to refer to the object passed as the first parameter.
4. New Binding Constructor call: new User() A freshly constructed empty object in the heap.

2. Explicit Binding: call vs. apply vs. bind

explicit-binding.js
function introduce(city, country) {
  return `I am ${this.name} from ${city}, ${country}.`;
}

const engineer = { name: 'Sarah' };

// 1. call: Invokes immediately, arguments passed comma-separated
introduce.call(engineer, 'London', 'UK');

// 2. apply: Invokes immediately, arguments passed as an Array
introduce.apply(engineer, ['London', 'UK']);

// 3. bind: Does NOT invoke immediately! Returns a brand new function with permanently locked 'this'
const boundIntroduce = introduce.bind(engineer, 'Tokyo');
boundIntroduce('Japan'); // "I am Sarah from Tokyo, Japan."

🎯 Top Frontend Interview Questions

Q: What happens when an object method is passed as a callback (e.g., setTimeout(user.logName, 1000)), and how do you fix it?

Answer: This is the famous Lost Context Problem. Passing user.logName extracts the raw function pointer without the object reference. When setTimeout executes the callback later, it invokes it as a standalone function, triggering Default Binding (where this is window or undefined).
Two Fixes:
1. Wrap in an Arrow Function: setTimeout(() => user.logName(), 1000); (retains lexical scope).
2. Explicit Binding with bind(): setTimeout(user.logName.bind(user), 1000);

Unit 4: Object-Oriented JS & OOP

9. Prototypal Inheritance & The Prototype Chain

Prototypes & __proto__

JavaScript does not have traditional classical inheritance like Java or C++. Inheritance in JavaScript is fundamentally prototypal: objects link directly to other objects via a hidden pointer link called the Prototype Chain.

1. The Prototype Chain Lookup Mechanism

When evaluating user.toString(), the engine performs the following step-by-step lookup:

  1. Checks if toString exists as an own property directly on user.
  2. If not found, follows the hidden internal pointer user.__proto__ to its prototype object.
  3. Traverses up the chain until found or reaching Object.prototype.__proto__ === null (end of chain). If still not found, returns undefined.

2. prototype vs. __proto__ Architecture

prototypes.js
// Constructor function
function Developer(name, specialty) {
  this.name = name;
  this.specialty = specialty;
}

// Attach shared methods to the prototype (Memory efficient!)
Developer.prototype.code = function() {
  return `${this.name} is writing ${this.specialty} code.`;
};

const dev1 = new Developer('Alex', 'JavaScript');
const dev2 = new Developer('Maya', 'C++');

// Both instances share the exact same function reference in memory!
console.log(dev1.code === dev2.code); // true
console.log(dev1.__proto__ === Developer.prototype); // true

🎯 Top Frontend Interview Questions

Q: What is the difference between prototype and __proto__?

Answer:
• prototype: A property that exists ONLY on constructor functions (and classes). It defines the blueprint object that will become the prototype of all instances instantiated with new Constructor().
• __proto__ (or Object.getPrototypeOf()): A property that exists on every object instance. It is the actual physical pointer pointing to that instance's prototype object.
Invariant: const obj = new Fn(); obj.__proto__ === Fn.prototype; // true

10. ES6+ Classes & Modern OOP Architecture

Classes, Super & Private Fields

ES6 classes provide cleaner, syntactical sugar over prototypal inheritance. Modern ES2022 introduces native private class fields (#privateField) for true language-level encapsulation.

1. Complete Class Architecture with Inheritance & Private Fields

classes-oop.js
class Account {
  #secretKey; // True private field (ES2022): Inaccessible outside class body!
  static bankName = "Enterprise Global Bank"; // Static property

  constructor(owner, initialBalance, secretKey) {
    this.owner = owner;
    this.balance = initialBalance;
    this.#secretKey = secretKey;
  }

  // Getter & Setter
  get displayBalance() {
    return `$${this.balance.toLocaleString()}`;
  }

  // Instance Method
  deposit(amount) {
    this.balance += amount;
    return this.balance;
  }

  // Static Factory Method
  static createDefault(owner) {
    return new Account(owner, 100, 'KEY-123');
  }
}

// Class Inheritance
class PremiumAccount extends Account {
  constructor(owner, balance, secretKey, cashBackRate) {
    super(owner, balance, secretKey); // Invokes parent constructor
    this.cashBackRate = cashBackRate;
  }

  // Method Overriding (Polymorphism)
  deposit(amount) {
    const bonus = amount * this.cashBackRate;
    return super.deposit(amount + bonus);
  }
}

🎯 Top Frontend Interview Questions

Q: Are ES6 classes purely syntactic sugar over prototypal inheritance, or are there real technical differences?

Answer: While classes compile to prototypal inheritance under the hood, they enforce several distinct technical behaviors:
1. Mandatory new: Invoking a class without new (Account()) throws an immediate TypeError. (Constructor functions silently run as default function calls).
2. Strict Mode Enforced: All code inside a class body runs automatically in 'use strict' mode.
3. Non-Enumerable Methods: All methods declared inside a class body are automatically configured with enumerable: false on the prototype.
4. TDZ: Classes are not hoisted into initialized memory; they live in the Temporal Dead Zone until declared.

Unit 5: Asynchronous JS & The Event Loop

12. The Event Loop Deep-Dive: Call Stack, Microtasks & Macrotasks

Concurrency & Event Loop

JavaScript is single-threaded, meaning it has only one Call Stack and can execute only one statement at a time. Concurrency and non-blocking I/O are powered by the Event Loop coordinating between Web APIs, the Microtask Queue, and the Macrotask Queue.

1. The Three Tiers of Execution Priority

Priority TierQueue NameAsynchronous Task TypesExecution Rules
Priority 1 Call Stack Synchronous JavaScript code (loops, calculations, console.log). Runs to absolute completion before any queued callbacks can execute.
Priority 2 Microtask Queue Promise.then/catch/finally, async/await continuations, queueMicrotask(). Drained to EMPTY after every single Call Stack frame completion, before rendering or macrotasks!
Priority 3 Macrotask Queue setTimeout, setInterval, DOM event callbacks, I/O. Event loop picks exactly ONE macrotask, executes it, then immediately checks and clears the Microtask Queue again!

2. Classic Event Loop Interview Puzzle

event-loop-test.js
console.log('1'); // Synchronous

setTimeout(() => {
  console.log('2'); // Macrotask
}, 0);

Promise.resolve().then(() => {
  console.log('3'); // Microtask
});

console.log('4'); // Synchronous

// Execution Order Output:
// 1
// 4
// 3
// 2

🎯 Top Frontend Interview Questions

Q: What happens if an infinite loop of microtasks is created via queueMicrotask() or recursive Promise.resolve()?

Answer: It completely starves the browser event loop.
Because the Event Loop specification requires the engine to completely drain the Microtask Queue before yielding control to the browser rendering pipeline or picking the next macrotask:
A recursive microtask generator prevents the browser from ever repainting pixels on screen, processing user clicks, or executing setTimeout callbacks. The entire web page completely freezes and stops responding.

13. Asynchronous JS: Callbacks, Promises Lifecycle & async/await

Promises & async/await

Asynchronous operations (network requests, timers, file access) in JavaScript evolved from Callback Hell to Promises (ES6) and finally to async/await (ES2017).

function timeoutPromise(promise, ms) {

Unit 6: DOM, Web APIs & Performance

14. High-Performance DOM Manipulation & Event Delegation

DOM Tree & Event Delegation

The Document Object Model (DOM) is an object-oriented tree representation of the HTML document. Direct DOM manipulations are among the most expensive operations in web applications.

1. The 3 Phases of Event Propagation

When an event occurs on a DOM element (e.g. clicking a button), it travels through three distinct phases:

  1. Capturing Phase: The event travels downward from window → document → <html> → <body> → down to the target parent.
  2. Target Phase: The event reaches the actual target element that triggered the action.
  3. Bubbling Phase: The event bubbles back upward through every ancestor up to window.

2. Event Delegation Architecture

Instead of attaching 10,000 separate event listeners to every row in a table or list, attach one single listener to the parent container and leverage event bubbling:

event-delegation.js
// 1 Listener handles millions of dynamic rows!
const table = document.getElementById('users-table');

table.addEventListener('click', (event) => {
  // Find nearest matching button trigger
  const deleteBtn = event.target.closest('.delete-row-btn');
  if (!deleteBtn) return; // Click occurred elsewhere

  const row = deleteBtn.closest('tr');
  const userId = row.dataset.userId;
  console.log('Deleting user ID:', userId);
  row.remove();
});

3. Batch DOM Updates with DocumentFragment

fragment.js
// Appending elements individually causes 1,000 separate browser reflows!
// Using DocumentFragment causes exactly ONE reflow:
const fragment = document.createDocumentFragment();

for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item #${i}`;
  fragment.appendChild(li); // Purely in memory
}

document.getElementById('list').appendChild(fragment); // 1 single Reflow!

🎯 Top Frontend Interview Questions

Q: What is the difference between event.target and event.currentTarget?

Answer:
• event.target: The exact physical element that received the user interaction (e.g. the inner <svg> or <span> inside a button).
• event.currentTarget: The element to which the event listener was explicitly attached (e.g. the parent <ul> or <button>). Inside an event handler function, this === event.currentTarget.

15. Networking, Web APIs & Optimization Patterns

Debounce, Throttle & Observers

High-performance web applications optimize high-frequency events (typing, scrolling, window resizing) using rate-limiting design patterns and asynchronous browser observer APIs.

1. Debouncing vs. Throttling

TechniqueCore MechanismIdeal Production Use Case
Debounce Delays execution until a specified quiet period has elapsed with no new events fired. Each new event resets the timer. Search bar autocomplete input, auto-saving drafts, window resize layout recalculations.
Throttle Guarantees execution at a regular fixed maximum frequency (e.g. at most once every $100\text{ms}$). Scroll position tracking, infinite scroll triggering, game loop input listeners.

2. Hand-Crafted Debounce & Throttle Polyfills

rate-limiters.js
// 1. Debounce Implementation
function debounce(fn, delay) {
  let timerId;
  return function(...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 2. Throttle Implementation
function throttle(fn, limit) {
  let inThrottle = false;
  return function(...args) {
    if (!inThrottle) {
      fn.apply(this, args);
      inThrottle = true;
      setTimeout(() => inThrottle = false, limit);
    }
  };
}

3. High-Performance IntersectionObserver for Lazy Loading

observer.js
// Replaces laggy window.onscroll listeners with native GPU-calculated intersection checks:
const imageObserver = new IntersectionObserver((entries, observer) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src; // Swap data-src to real src
      observer.unobserve(img);   // Disconnect observer for this image
    }
  });
}, { rootMargin: '100px' }); // Preload 100px before appearing in viewport!

document.querySelectorAll('img[data-src]').forEach(img => imageObserver.observe(img));

🎯 Top Frontend Interview Questions

Q: How does AbortController cancel pending fetch HTTP requests when a user rapidly types in a search bar?

Answer: When a user types rapidly, previous network requests are obsolete and cause race conditions if an older request returns after a newer one.
Using AbortController:
let currentController = null;
function search(query) {
if (currentController) currentController.abort(); // Cancel previous ongoing request!
currentController = new AbortController();
fetch(`/api/search?q=${query}`, { signal: currentController.signal })
.then(r => r.json())
.then(data => updateUI(data))
.catch(err => { if (err.name !== 'AbortError') console.error(err); });
}
